# Cutover re-sync + Electron OAuth redirect fix (2026-06-09)

> Moved from the `project-state.md` "Recently completed" section of branch `workflow/cutover-resync-2026-06-09` (tip 47a765a) during the 2026-09-29 consolidation, because main split project-state into a lean snapshot plus per-run files.

- **Electron OAuth callback fix + v1.12.14 release (2026-06-09, branch `workflow/cutover-resync-2026-06-09`, commit `c5d4c7d`).** First-time Google sign-in froze on a genuine Intel Mac (secretary `info@`): clicking the account "did nothing." Root cause — `electron/main.js` intercepted the `bulletingen://auth-callback` deep link only on `webContents` **`will-navigate`**, but a first-time account-picker completes via a server-side 302 → **`will-redirect`**, which was never caught, so the BrowserWindow tried to load the custom-protocol URL and silently failed. Users with cached Google consent (e.g. AJ's machine) took the `will-navigate` path and were unaffected — explaining "works for me, not her." Fix: a shared handler bound to **both** `will-navigate` and `will-redirect`. Diagnosis confirmed the sidecar was healthy (port 8765 responding) and the freeze was renderer/redirect-side, not `/api/me`. Shipped as **v1.12.14** (tag pushed from the branch; `release-electron` run 27240406059 green — Intel x64 + arm64 DMG signed/notarized; APP_VERSION fallback bumped to 1.12.14). Intel DMG: `Bulletin.Generator-1.12.14.dmg`. **Known latent issue (separate):** magic-link login still throws a PKCE `code_verifier` error in Electron — OAuth is the primary path; magic-link hardening deferred.
